# ADR-0009：平台场景无关——不锁定付费行业，以参考场景包支撑试点

- **状态**：✅ 已采纳
- **日期**：2026-08-15
- **背景**：登记册遗留开放项「首个付费行业 ⏸ 后置（阶段 3 启动前必须拍板）」；执行计划 T3.1 原按「锁定 1 家制造业/ITSM 试点组织」设计，隐含平台对垂直行业下注。
- **关联**：`docs/execution-plan.md` 阶段 3、ADR-0004（单组织私有部署优先）、`examples/connectors/README.md`

## 背景

Bycall 的差异化卖点是「组织授权下的可靠执行」（治理脊柱），而非任何单一行业的业务深度。
项目是**开源项目**、单人维护：没有销售杠杆去支撑行业深耕，押注制造业或 ITSM 都会把
平台能力做窄、把通用治理价值稀释成行业方案。同时，垂直场景（设备运维、IT 服务台、……）
真正需要的是「能安全接入自己系统、自己定义角色与流程」的能力，而不是平台替他们选行业。

## 决策

1. **Bycall 定位为场景无关的开源安全可控 agent 平台**。平台核心（`src/bycall/`：
   governance / agent / rag / tools / mcp / admin / api / gateway）不得引入任何行业特化
   概念与数据；行业词汇只允许出现在 `examples/`、docs 示例与测试数据里。
2. **仓库交付「参考场景包」**（`examples/connectors/` + `scripts/seed_reference.py` +
   `make seed-reference`）：2 个示例 MCP 连接器（工单 + 库存）+ 3 类示例角色
   （一线/主管/访客）+ demo 账号，演示接入方式与治理语义（白名单、destructiveHint →
   HITL 审批门、身份透传）。参考场景包可整体删除而不影响平台运行。
3. **真实试点接触不限行业、并行推进**（自阶段 0 已启动）：试点是验证渠道与数据来源，
   不是产品方向；试点组织的场景用「复制参考场景包改造」的方式落地，不回写平台核心。
4. **登记册开放项「首个付费行业」就此关闭**：结论为「不锁定行业」。

## 备选方案

- **押注制造业设备运维**（T0.1 默认项）：否决——单人开源项目无销售杠杆，押注收窄平台。
- **押注 ITSM**（T0.1 备选）：否决——同上，且与制造业二选一本身是伪命题。
- **双行业并行做深**：否决——直接违背执行计划「冻结非核心」总原则。

## 后果

- 正面：平台价值主张聚焦治理本身；采用者自助接入门槛由参考场景包拉低；开源传播
  不受行业标签限制；T3.1 的「可跑通」验收不再被商务进度（锁定试点组织）阻塞。
- 负面：失去单一行业的深度打磨机会；试点阶段（T3.2/T3.3）的「三条端到端流程」
  定位调整为**参考流程**，真实效果数据仍需等首个采用组织落地后才能产出。
- 执行：`docs/execution-plan.md` T3.1 已按本 ADR 改写；平台核心出现行业概念的 PR
  应视为违红（架构红线之外的定位红线）。

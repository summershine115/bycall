# ADR-0013：控制台面板重组——取消"默认员工" + 实例/资产/渠道三分

- **状态**：✅ 已采纳（用户 2026-09-22 拍板：默认员工本就不该存在；资产与渠道从数字员工入口拆出；
  列表瘦身 + 展开行；详情改左锚点分段并补「生效预览」）
- **日期**：2026-09-22
- **背景**：`/agents` 面板把三类生命周期完全不同的东西塞进一条 tab 条——① 数字员工实例（个体）；
  ② 组织级共享资产（提示词版本 / 模型 / Skill / MCP 工具 / 知识库 / 文档，跨实例存在）；
  ③ 系统凭证（渠道接入）。同时平台在 `init_db` 里灌了一条 `Agent(name="default")`「默认助手」，
  但 `is_default` 在运行时**零消费**（runner / capability / im_handler / gateway 均不读，全仓仅
  admin CRUD、schemas、db 种子与前端文案引用），"默认实例兜底"只存在于 UI 措辞与 ADR-0012 §2 的
  表述中——实际无实例归属的会话走的是"角色 → 全局激活"链路。列表 9 列把 `skills`/`allowed_tools`/
  `knowledge_scope_tags` 覆盖项原样 dump（留空=沿用角色，展示的不是生效结果），详情 435 行单页 6 段
  顺序堆叠、无分段导航，「改可见性要滚到底」且看不到任何"对某角色实际生效什么"。
- **关联**：ADR-0012（多 Bot 渠道与旧 IA）、ADR-0005（ABAC/能力集）、`architecture.md` 红线 #1/#2、
  `docs/execution-plan.md` T3.5 / T3.6、§4 冻结清单（前端打磨）

## 背景

用户的原始反馈（2026-09-22）：**「默认员工是不存在的，不应该有默认员工；页面太复杂了各种功能
应该重新规划放置；员工列表也不清晰，配置点开后翻看很麻烦」**。诊断后确认四点：

1. 默认员工由 `db.py::_seed_defaults()` 灌入，删除它**不改变任何运行时行为**（capability 对
   `agent_id=None` 早已有明确定义：角色基线 + 全局激活人格/模型）。
2. 面板复杂度的根因是三类关注点混在一个 Hub：配一个员工却要面对一排与"这个员工"无关的 tab。
3. 列表单元格展示"覆盖项"而非"生效结果"，管理员无从判断实际能力（治理产品里这属于误导）。
4. 详情无导航、无脏标记、无生效视图——配置行为的可理解性差。

## 决策

1. **取消"默认员工"概念（彻底移除）**
   - `init_db` 不再灌任何 `Agent`；首个实例必须由管理员显式创建（空组织就是空的）。
   - `Agent.is_default` 字段、`AgentCreate/Update/Out` 字段、`_ensure_single_default`、
     删除守卫（"默认实例不可删"）、`Agent.select_default()`、前端"设为默认/默认实例/默认"
     标签与 `Chat` 的"默认实例（未指定）"选项全部移除。
   - 存量清理：`init_db` 幂等调用 `_cleanup_legacy_default_agent()`——**仅当**该行完全等于种子
     足迹（`name='default'` + 描述/渠道未被改过 + 无专属凭证 + 无能力覆盖 + 无会话引用）才删除，
     否则保留并记日志。管理员动过的实例一律当作真实数据，升级过程绝不误删。
   - 语义澄清：全局默认 Bot 是**渠道入口**，不是员工。其入站消息 `agent_id=None`，会话不归属
     任何实例，按对话者角色 + 全局激活链路回答（与实例存在与否无关）。
2. **信息架构三分（关注点分离）**
   - 「数字员工」= 实例列表 + 实例详情（个体视角）。
   - 「能力资产」新分组 = 提示词版本 / 模型管理 / Skill 管理 / MCP 工具 / 知识库 / 文档管理
     （组织级共享零件库）。
   - 「渠道接入」独立页 = 全局默认 Bot 凭证 + 各实例专属连接总览（系统凭证）。
   - 旧路径 `/agents/{channels,prompts,models,skills,mcp,knowledge-bases,knowledge}` 保留
     重定向到新一级页面（深链不破，保留 query）。
3. **列表瘦身 + 渐进披露**：主表只留「实例 / 装配 / 接入 / 启用 / 操作」五列，能力边界明细移入
   展开行；装配列显示**人格、模型的生效来源**（实例绑定 or 沿用/全局激活）与覆盖计数，
   不再冒充生效结果；KPI 去掉"默认实例"卡（改为实例总数 + 专属渠道连接）。
4. **详情改左锚点分段 + 生效预览**：六段（基础信息 / 人格与模型 / 能力边界 / 可见性 / 渠道接入 /
   生效预览）左侧切换、右侧只渲染当前段；每段保存按钮就地可见，按基线比对给出脏标记与
   「放弃修改」；未接入专属渠道的实例明确标注"IM 消息不会进入该员工"，不再暗示走默认 Bot。
5. **生效预览的数据源是治理脊柱本身**：`POST /api/admin/policy/simulate` 新增可选 `agent_id`
   （请求与响应均补该字段），按实例收窄后计算 `CapabilitySet`——与数据面同源，前端不自行推算
   能力边界（避免"预览与真实不一致"）。人格/模型链路仍由前端按 config 链（实例 > 角色 > 全局激活）
   展示，属展示层推导，不参与判定。
6. **冻结清单豁免**：§4 冻结的是"前端视觉/主题/排版打磨"。本次是用户明确提出的信息架构与
   可理解性返工（阶段 3 真实使用验证的必要条件），按冻结清单"真实使用或审计明确提出需求时"
   的恢复条件执行，一并登记为 T3.6。

## 备选方案

| 方案 | 结论 |
|------|------|
| 保留 `is_default` 作为可选"兜底实例"（不自动创建） | 拒绝：要让"兜底"名副其实必须改 `im_handler`/`runner` 把无归属入站路由到某实例，属新能力；现状 `agent_id=None` 已有明确定义，凭空多一个概念只会再制造一次"UI 承诺 ≠ 运行时行为" |
| 只删种子，保留字段与 UI | 拒绝："默认实例"标签与"设为默认"按钮留着，等于继续展示一个没有运行时含义的状态 |
| 存量 `default` 实例一律删除 | 拒绝：无法区分"未被碰过的种子"与"管理员改过名字/配过能力"的真实实例，会误删用户数据 |
| 资产页留在 Hub 内做二级"资产库"页 | 拒绝：资产跨实例存在，挂在员工入口下仍会让"配一个员工"变成逛杂物间 |
| 列表改卡片网格 | 暂不采用：当前实例数为个位数，卡片更漂亮；但表格的行内状态/接入操作与未来增长更稳，先用瘦身表格，视觉形态留待真实使用反馈 |
| 详情用顶部 Tab / 向导 | 拒绝：Tab 与旧分段等价（仍无导航语义与脏标记）；向导适合偶尔创建、不适合高频微调 |

## 后果

- **正**：面板语义与运行时行为对齐（不再有"看不见的默认员工"）；员工入口只管员工；列表可扫读、
  详情免翻找；"留空=沿用角色"第一次变成可验证的答案（生效预览），治理产品的核心承诺变得可见。
- **负/边界**：`Agent.is_default` 列在存量库中保留不删（SQLite 删列有风险且无收益），模型层不再映射
  该列；`/api/admin/agents` 的响应不再含 `is_default`（控制面 API 的破坏性变更，仅 admin 控制台消费，
  前端已同步）。
- **风险**：升级时若管理员曾把 `default` 改成一个真实实例，则不会被清理而是留在列表里（有意为之，
  属保守取向）；空组织首次进入面板是空态——用引导文案承接，不自动创建任何数据。
- **验证**：`tests/unit/test_agent_no_default.py`（新库零实例 / 种子清理 / 动过的保留 / 有会话引用保留 /
  旧库带 `is_default` 列不报错）、`tests/unit/test_policy_simulate.py`（实例收窄、实例不存在 404、
  可见性先于能力集）、`make ci-local` 全绿 + `npm run build` 通过 + 真实页面走查。

- **2026-09-22（slug 修订）**：新建实例不再要求管理员填 slug——它不是寻址键（全仓无任何按 name
  查 Agent 的运行路径，寻址一律用 `id`；模型/接口文档的「API 寻址键」表述已订正为「内部标识」），

  `agent-<4 位随机>`，同名冲突追加随机后缀。`AgentCreate.name` 变为可选（显式传入仍兼容，
  非法格式 422、重复 409）；前端新建表单去掉该字段、列表行改显描述（内部标识移入展开行）。

- **2026-09-22**：首次落地。同批修正 ADR-0012 表述（其 §2 的"路由到默认实例"实际语义为

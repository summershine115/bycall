## 1. 背景与边界

- **平台定位**：Bycall 是场景无关的安全可控 agent 平台，`src/bycall/` 不含行业词汇；`examples/` 与本规格是参考包，可整体删除。
- **复用 T3.1**：通用记录系统即 `demo-ticket`/`demo-inventory`（`examples/connectors/`），不新增连接器。工具名保持 `mcp__demo-ticket__*` / `mcp__demo-inventory__*`，仅在文档与演示话术中去行业化（称"通用记录/通用物料"而非"工单/备件"）。
- **RAG 后置**：本规格 RAG 仅验证管线（预算/去重/投毒软降级）不报错；真实文档与"故障诊断"类问答待用户提供文档后再灌入验证，不计入本任务出口门。

## 2. 三条平台级流程（去行业化命名）

### 流程 A：查询-创建闭环（通用工具链）

> 演示：`allowed_tools` 按角色过滤 + 多轮参数补全

| 步骤 | 操作 | 治理点 |
|------|------|--------|
| A1 | `demo-guest` 问"你能查/建记录吗" | LLM 工具列表为空（`guest.allowed_tools=[]`），只能文本拒答/引导联系管理员 |
| A2 | `demo-tech` 问"查一下 T-1001" / "搜 bearing" | 可见 `query_ticket`/`list_tickets`/`search_parts`/`get_part_stock`，调用成功，返回脱敏截断 |
| A3 | `demo-tech` 说"帮我建一条标题为'测试-平台流程A'的记录" | 调用 `create_ticket` 成功，返回新 ID；多轮缺参时 LLM 追问补全 |
| A4 | `demo-lead` 复述 A2/A3 | 同 technician，但多一次可见高危工具（不触发） |

**验证**：同一问题不同角色工具可见性不同；`guest` 绝不触发工具调用（`tool_calls` 为空）。

### 流程 B：高风险操作 HITL 回推（审批门）

> 演示：`destructiveHint` → 审批单 → 三档授权 → 推送

| 步骤 | 操作 | 治理点 |
|------|------|--------|
| B1 | `demo-tech` 尝试"预留 BRG-6205 x2" / "关闭 T-1001" | 网关 `destructiveHint` 拦截，生成 `ApprovalRequest`（状态 `pending`），LLM 回复"已提交审批" |
| B2 | 控制面/IM 审批队列中，`demo-lead` 以 `supervisor` 批准（选档 `once`） | 审批通过后系统自动重放工具调用，写入 `reserve_part`/`close_ticket`，落库 `ApprovalGrant` |
| B3 | 发起员工 IM 收到主动推送"你的预留/关单已执行，结果: ..." | 复用 M6 推送（`gateway`），验证 `tool_results` 脱敏 |
| B4 | 同工具再次请求 | `once` 需重新审批；`session` 当会话内免审；`always` 跨会话免审（复用 T3.3 已落地逻辑） |
| B5 | `demo-tech` 即使白名单误配也无法直调 `close_ticket` | 连接器侧 `bycall_role` 复核二次拒绝（纵深防御） |

**验证**：未审批时工具不执行；三档授权语义正确；推送到达；连接器侧二次校验有效。

### 流程 C：多轮上下文与能力边界感知（会话隔离 + Runtime Context）

> 演示：会话隔离 + 上下文连续 + 能力主动披露

| 步骤 | 操作 | 治理点 |
|------|------|--------|
| C1 | `demo-tech` 单聊多轮：先问"我是谁/我能用什么工具"，再问"刚才那条记录标题是什么" | Runtime Context 正确披露身份/工具；第二轮引用首轮创建的记录（历史加载） |
| C2 | `demo-tech` 与 `demo-lead` 同问"你能关单吗" | 回答不同（tech: 需审批/无权限，lead: 可审批），证明能力按角色分发 |
| C3 | `demo-tech` 开新会话问"上一会话的记录" | 隔离：新会话看不到旧会话上下文（`conversation_id` 隔离） |
| C4 | 任意角色问超出 `knowledge_scope_tags` 的知识 | RAG 预过滤返回空或低相关，LLM 引导"需相应权限"，验证 `visible_kb_ids` + `level` 过滤（无文档时仅验证不报错、审计有 `context_report`） |

**验证**：跨会话/跨用户不串台；能力披露与实际白名单一致；RAG 空库不崩。

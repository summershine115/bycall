# ADR-0014：控制台导航精简合并——19 项入口 → 8 项（Hub tab 容器 + 顶栏设置入口）

- **状态**：✅ 已采纳（用户 2026-09-23 拍板：侧边栏内容太多，选「激进」档位精简合并）
- **日期**：2026-09-23
- **背景**：ADR-0013 的三分（实例 / 资产 / 渠道）解决了「关注点混在一个 Hub」，但没有解决
  **入口本身太多**：侧边栏 6 组 19 项，1440×900 下导航区实测 **1200px 内容 / 792px 可视**——
  必须滚动才能看全，日常入口的可见性被稀释（用户反馈：「侧边栏内容太多了，有没有办法精简合并一下」）。
- **关联**：ADR-0013（三分与旧路径重定向约定）、ADR-0012（多 Bot 渠道与更早的 IA）、
  `doc/execution-plan.md` §4（前端打磨冻结 + 恢复条件）、T3.7

## 背景

侧边栏是控制台唯一的常驻导航面。19 项的问题不是「功能多」（这个阶段功能确实多），而是
**同一层里混了三种不同粒度的东西**：功能分区（组织/员工/资产/运行）、单例系统页
（运行时设置、渠道接入）、以及同一实体的上下层（知识库 ↔ 文档管理、用户 ↔ 角色 ↔ 策略模拟）。
结果是每一项都占一行，谁都不突出，且超过一屏后需要滚动。

## 决策

1. **同源页面合并为 Hub（tab 容器）**：一级页面由 19 个收敛为 8 个导航项，**页面一个都没删**——
   16 个原一级页各自成为某个 Hub 的 tab，2 个独立页 + 仪表盘保持一级：

   | 侧边栏项（8） | 路由 | 页内 tab（原一级页） |
   |---|---|---|
   | 仪表盘（首页位） | `/` | — |
   | 组织与权限（组织与身份） | `/org` | 用户管理 · 角色与权限 · 策略模拟 |
   | 数字员工（数字员工） | `/agents` | 实例列表 · 渠道接入 |
   | 能力资产（能力资产） | `/assets` | 提示词版本 · 模型管理 · Skill 管理 · MCP 工具 · 发布与回滚 |
   | 知识库（能力资产） | `/knowledge` | 知识库 · 文档管理 |
   | 运行记录（运行与监督） | `/runtime` | 会话管理 · 任务执行 |
   | 审批队列（运行与监督） | `/approvals` | —（独立页，保持醒目） |
   | 审计与指标（运行与监督） | `/audit` | 审计日志 · 运营指标 |

2. **首页位**：仪表盘不占分组标签，固定排在品牌之下——「回首页」不是功能区。
3. **运行时设置移入顶栏齿轮**：低频、系统级配置（解析引擎等）不占导航位；`/settings` 路由不变，
   顶栏入口在被访问时高亮。
4. **侧边栏 4 组**：组织与身份 / 数字员工 / 能力资产 / 运行与监督。
5. **tab 即 URL 状态**：`?tab=<key>`；非法或缺失值归一化写回（链接永远可复制），
   切换 tab 用 `router.replace`（tab 是同一页面的视图模式，不占用浏览历史，返回键仍回上一个页面）。
6. **旧路径全部保留重定向**（沿用 ADR-0013 约定）：21 条对照表覆盖合并前的每个入口，
   含 `/knowledge?kb_id=N` 这类深链——落到文档 tab 且保留 `kb_id`，上下文不丢。
7. **单一真相源 `frontend/src/nav.js`**：侧边栏分组、Hub/tab 定义（含懒加载组件）、面包屑归类、
   tab 解析规则集中于此；路由表中的 Hub 路由由它生成——杜绝「侧边栏改了、路由忘了」的漂移。
8. **Hub 内页头去重**：Hub 通过 `provide('bcHubMode')` 告知子树；`PageHeader` 据此省略与 tab 名
   重复的一级标题，只保留描述与操作区，避免「tab 名 + 同字大标题」的双层重复。
9. **冻结清单豁免**：§4 冻结的是「前端视觉/主题/排版打磨」，本次是用户明确提出、且影响日常
   可达性的信息架构精简，按冻结清单的恢复条件（「真实使用或审计明确提出需求时」）执行，
   一并登记为 T3.7。

## 备选方案

| 方案 | 结论 |
|------|------|
| 只把分组改成手风琴（页面与路由全不动） | 拒绝：19 个入口一个不少，只是不同时占屏——问题从「要滚动」变成「要点开」，日常点击成本反而上升 |
| 把资产 4 页合并进一个 Hub、其余不动 | 拒绝（本次口径）：用户选择「激进」档位，一次性把三类同源页面全部收敛，避免二次返工 |
| 撤销 ADR-0013 的三分，恢复「数字员工 Hub」 | 拒绝：三分解决的是关注点混淆，与本次的入口数量问题是两回事；渠道接入并入的是**页面 tab** 而非回到员工 Hub 语义 |
| 侧边栏做成二级菜单（分组可展开/收起） | 暂不采用：同一屏 8 项已无溢出，二级折叠增加交互层级；真实使用若显示需要更多入口再议 |
| 保留 `settings` 在侧边栏末位 | 拒绝：系统级低频页与功能区混排，正是「每项都占一行、谁都不突出」的成因之一 |

## 后果

- **正**：导航区不再溢出（1440×900 实测 792px / 792px，8 项 4 组，无需滚动）；同源页面在同一屏内
  用 tab 切换，上下文连续（如「知识库 ↔ 文档」不再跨页跳转）；旧链接、书签、深链一律可达。
- **负/边界**：原一级页面多了一次 tab 点击；tab 状态进入 URL（`?tab=`）；`PageHeader` 在 Hub 内
  不再渲染 h1（语义由 tab 承担）。合并后的页面成为「多 tab 容器」，新页面加入时须在 `nav.js`
  登记 tab，而不是直接往侧边栏塞一项。
- **风险**：Hub 内的 tab 容器使用 `lazy`（首次激活才挂载并拉取数据），后台 tab 的内容会保留在
  DOM 中（切回不重载）——对只读列表无影响，对时效敏感的页面由各自刷新按钮兜底。
- **验证**：`npm run build` 通过；浏览器实测 18/18 旧路径重定向（含 3 条 kb_id 深链）命中预期
  URL 与 tab、16/16 Hub tab 渲染出自身内容、侧边栏 8 项 4 组不溢出、顶栏齿轮进入 `/settings` 并
  高亮、旧版对照实测溢出 1200px/792px。

## 0. 问题链（三轮讨论的递进）

1. "Agent 安全"是否是太庞大的命题？bycall 是否应该专注更具体的命题？
2. governance 是否降低 agent 能力？如何避免 agent 越过护栏？治理能否单独抽象？
3. **定位收敛**：开源到 GitHub 作为个人项目、不以盈利为目的——数字员工赛道已有优秀产品，
   但安全护栏 / 检索层治理的开源方案稀缺。

本文整理对这三个问题的观点，核心结论在 §1，论据在 §2–§6，落地与待拍板在 §7–§9。

---

## 1. 核心结论（一段话）

**"Agent 安全"是行业品类，不是 bycall 的命题；bycall 的命题是"组织授权下的可靠执行"，
安全是这一命题可验证的副产物。** 在非商业、个人开源的前提下，建议定位再收一格：

> **Bycall —— 一个策略活在代码层的组织数字员工参考实现：**
> **身份 → 能力集 → 召回前 ACL → 工具白名单 → HITL → 审计，六道闸全部有评测证明。**

数字员工平台是让治理脊柱**可证伪**的载体（reference app），不是竞争目标；
不与通用治理工具包（微软 AGT 已占位）竞争，不与 Dify/Coze 拼平台广度。

---

## 2. 观点 A："Agent 安全"是品类，不是命题

**论点**：作为品类，"agent 安全"涵盖提示注入防御、沙箱逃逸、运行时监控、多智能体协议
安全、供应链、红队评测——每项都是开放研究问题，大厂与创业公司涌入，至今没有独立产品
形态（谁付费？为什么不靠平台自带能力？）。单人项目以"产品"身份进这个品类没有胜算。

**但 bycall 的文档从未把自己放进这个品类**：

| 文档 | 表述 |
|---|---|
| `product-design.md` §0 | 面向组织的数字员工系统——治理是使产品能在组织里部署的**信任架构**，不是卖点 |
| `product-strategy.md` §1 | "企业数字员工的治理与执行平台"，明确否定两个陷阱：不做通用搭建平台、不把价值归因于 RAG/LangGraph/MCP |
| `execution-plan.md` §1 | 唯一主轴："组织授权下的可靠执行" |

用词辨析：bycall 做的是 **governance（组织授权下的受托执行）**，"安全"是其可验证的副产物。

**两个方向的反面警示**：

- **太宽**：以"agent 安全产品"自居 → 进入无产品形态的品类，与全行业研究问题正面竞争。
- **太窄**：收窄成"治理中间件 / policy 引擎" → 纯策略层是成熟平台半年能吸收的 feature，
  不是产品；价值在完整闭环（IM 常驻 + 治理脊柱 + 受控执行 + 可验证发布）。

**命题不缺再收窄，缺证明**：执行计划诊断的致命问题是 #1"零真实使用验证"，不是命题太大。
若将来要再收窄，唯一有意义的轴是"先服务谁"（第一个真实采用者的场景由使用数据选出），
而不是现在在文档里少承诺哪条安全性质。

## 3. 观点 B：治理不降低授权域内的能力

**论点**：治理过滤的是"模型**看到什么**"，不是"模型**怎么思考**"——授权范围内天花板不降。
真正降能力的是另一条路线：LLM-as-guardrail（第二个模型当裁判审查输出）——误拒、延迟、
体验劣化。bycall 的策略在代码层确定性判定：放行的请求以原生质量执行，拒绝快速且可解释。

两个反直觉的**增益**：

- 无权工具根本不进工具列表（`filter_tools`），LLM 选项更少、选择更准；Runtime Context
  主动告知能力边界，减少能力幻觉；
- 破坏性操作不是"能力丢失"而是"能力延后"——HITL 审批三档让 deny 有一条走向 yes 的路。

**唯一真实的能力损失：边界误拒（over-denial）**。对策不在削弱脊柱，而在三件事（多数已在设计内）：

1. **ABAC 精度**：部门∧职级∧密级，边界贴得越紧误拒越少（`policy.py` 中 dept 未接是已知剩余项）；
2. **策略模拟器**（T1.8 已落地）：admin 能看见"为什么看不见"；
3. **评测双向计量**：evals 同时锁定"越权召回 = 0"**和**"合法任务成功率"——误拒在 bycall
   被当作质量回退处理，不是可接受成本。

换个角度：对组织而言，**不受治理的能力 ≈ 不可部署的能力**——治理把可部署能力从零撑到
整个授权域。

## 4. 观点 C：防"越过护栏"的结构性答案——护栏不跑在 agent 里，就无处可绕

**论点**：LLM 只能"请求"，判定全在它够不到的地方。落到当前代码是六道闸 + 两道兜底：

| # | 闸 | 机制 | 位置 |
|---|---|---|---|
| 1 | 信任根 | 身份来自 IM 平台令牌→用户记录，模型无法"自称是谁" | 治理脊柱入口 |
| 2 | 看不到 | 无权工具不进工具列表（"看到不让调"都不存在） | `tools/gateway.filter_tools` |
| 3 | 调了也过闸 | 执行时 capability check + 连接器侧 `bycall_role` 复核（跨进程纵深） | 网关 + MCP |
| 4 | 召回前过滤 | `build_acl_filters` fail-closed，无权知识**从未成为 prompt token**——注入无从泄露不存在的东西 | `rag/retrieve` |
| 5 | 回流也过滤 | `sanitize_tool_result`：有权工具的返回照样脱敏 + 截断，未声明类型默认裁剪 | `tools/redactor.py` |
| 6 | 跨时间重算 | `reload_user_and_compute_cap`：审批等待 / 任务暂停后用**最新**用户状态重算，撤权即刻生效 | 审批 / Step 执行器 |

非权限兜底两道：工具回路迭代上限（防费用 DoS）；`eval-security` 五类攻击 × ≥3 用例进 CI，
配置变更回放比对，回退即阻断发布（发布门）。

**必须诚实划清的边界**：这套体系保证的是"**越权不可能**"，不保证"授权范围内的错误行为
不可能"。权限管不了的两类残余：

- **confused deputy**：agent 用*有权的*工具做蠢事（如把有权看到的敏感内容写进有权的出站
  通道）——对策在参数级策略、provenance 标注、审计，这是真正的开放难题；
- **提示注入降质**：注入仍可能造成"越权范围内"的错误动作——对策是注入标注降权 + 审计
  （T1.9），不是权限的职责。

纵深防御的含义：**权限（事前）+ 审批（事中）+ 审计/评测（事后）各管一段**。开源叙事中
这条边界要主动讲清楚——不过度承诺是可信度的一部分。

## 5. 观点 D：治理的抽象边界——决策可抽象，执行必须嵌入

**架构上已经抽象出来了，且缝是干净的**（2026-09-21 以 codegraph 核实）：

- `governance/` 不 import `agent/` 或 `rag/`，依赖单向（agent/rag 消费 governance）；
- `policy.py` 是纯函数、不碰 DB，模块文档自称"治理脊柱与检索层之间唯一的翻译层"；
- 策略模拟器（T1.8）之所以成立，正因为控制面与数据面调**同一个**决策函数。

**正确的抽象边界**：

> **决策**（能力集计算 / policy 求值 / 脱敏策略）= 纯函数，可测试、可模拟、可复用；
> **执行**（召回前注入 filter、构建工具列表时过滤、结果回流的 sanitize）= 必须长在管线内部。

**不建议拆独立库 / 独立服务**：外挂治理 sidecar 只能在周界拦截"agent 想调工具 X"，但最硬的
保证恰恰在 LLM 的**前后**——召回前过滤要求 filter 进向量检索调用内部，结果脱敏要求包住
工具输出进上下文之前。sidecar 覆盖不了这两个泄漏面，只能做最简单的 30%。跨边界真正该
携带的是**断言而不是执行**——MCP capability token 让治理判定随调用传播到连接器侧复核，
已是正确形态。

对个人开源项目的修正（结合 §6）：不是"不抽象"，而是**不与通用治理工具包竞争**——把六道闸
做成文档清晰、可被抄走的架构模式（每道闸配代码指针），比发布一个弱周界 SDK 有价值。

## 6. 观点 E：开源定位——非商业目标反转商业逻辑，但窗口在收窄

### 6.1 非商业反转了此前的商业判断

商业世界里"被平台吸收"是死；开源世界里**被吸收、被抄走架构就是影响力本身**。单人可维护性：
追平台广度不可能，守一条脊柱做深可行。

### 6.2 现状调研（2026-09-21）

- **[Microsoft Agent Governance Toolkit](https://github.com/microsoft/agent-governance-toolkit)**
  （约 6.3k stars，MIT，Public Preview）：通用治理内核——`govern(my_tool, policy.yaml)`
  包住任意工具调用，多语言 SDK，主打 OWASP Agentic Top 10 覆盖。其 README 论点与
  bycall 红线同构："Prompt-level safety … is not a control surface … intercepted in
  deterministic application code *before* the model's intent reaches the wire."
  - 好消息：核心论点已被行业验证（OWASP LLM01 / Agentic Top 10 完成了市场教育），bycall
    不再需要布道。
  - 坏消息：**通用治理工具包赛道刚被微软占位**，个人项目不该也没必要去拼。
- **检索层治理仍是散点**：agentic-rag-authorization、rerag-rebac（Ory）、AegisRAG 等均为
  小项目；"向量库行级权限是大多数 RAG 团队跳过的问题"目前只是
  [博客共识](https://tianpan.co/blog/2026/04/17/vector-store-access-control-rag-rls)，
  没有一个**跑起来的完整系统**把它做实——这正好是 bycall 已经做完的事。

### 6.3 定位：不是工具包，是参考实现

| | AGT（微软） | Dify / Coze | Bycall |
|---|---|---|---|
| 形态 | 治理内核库，自己接线 | 广度平台，治理是配置项 | **盖好的房子**：真跑起来的组织数字员工 |
| 检索层 ACL | 不覆盖（只拦工具调用周界） | 粗粒度 | **召回前过滤**——无权文档从未成为 prompt token |
| 结果回流脱敏 | 周界拦截 | 弱 | 进上下文前脱敏 / 截断 |
| 多用户信任模型 | 不管 | 不管 | agent ≠ user，会话隔离键 |
| 证明 | 合规映射 | 无 | **五类攻击 × evals，ASR = 0** |

AGT 是往自己栈里装的内核；bycall 是"把脊柱从第一天砌进去、盖完并证明可住"的参考实现。
观点 D 的"决策可抽象 / 执行必须嵌入"在此兑现为定位：**bycall 卖的正是执行深度**——
两个周界拦截够不到的泄漏面（召回前、回流后），加上 HITL 闭环与发布门。

### 6.4 对 execution-plan 主方向的影响（我的判断，供权衡）

不改变主轴（治理优先本来就是主轴），只改变**叙事与出口门表述**：开源语境下"真实使用
验证"（阶段 3）的对应物是**陌生人可复现**——从 clone 到 `make seed-reference` +
`make ci-local` 全绿一条命令链。真实企业使用从"目标"降为"最好的副产品"。
此条若采纳应在新 ADR 中一并明确（编号以登记册为准），避免与 execution-plan 出口门表述冲突。

## 7. 若走此路：资产清单与待办

**已在仓库里的资产**：

- 一句话论点："策略活在代码层，不在提示词层——一个你能看着五类攻击全部失败的数字员工。"
- **信任 demo**：`make seed-reference` → `make eval-security`，从 clone 到"看攻击被拦"。
  治理平时不可见，攻击失败那一刻才可见——这是治理项目最强的钩子。
- 决策登记册 / ADR / `doc/gaps.md` 的诚实性：绝大多数开源项目不展示决策过程，现成的差异化。
- 六道闸全部有代码指针与测试锁定（观点 C 表格可直接变成对外文档）。

**需要补的（按价值排序）**：

1. **OWASP Agentic Top 10 映射表**（六道闸 → 对应条目）：行业正在用这套词汇做评估，
   AGT 连徽章都挂了；用同一语言说话成本极低、可信度收益高。
2. **双语 README**：AGT 连日/中/韩版都备了，这个赛道是 table stakes；中文文档保留作深度层。
3. **README 重写**：以治理叙事开篇（现状 README 讲的是平台功能）。
4. **开源前 secret 扫描**：清理真实企微凭证、内网 host（evals/demo 文档、`.env` 样例等）。
5. License：建议 **MIT**（赛道惯例：AGT、QM 均为 MIT）。

## 8. 诚实的代价（预期管理）

- **受众是架构师 / 安全工程师，不是黑客玩具受众**：治理是"买家特性"，star 涨得会比酷炫
  agent 项目慢，但读者信号强。不用 star 速度衡量成败。
- **单人维护靠冻结清单守住**：execution-plan §4 的冻结纪律在开源后更重要，不是更松。
- **文档语言**：深度文档保持中文没问题（AGT 也有 i18n 分层），但入口层必须英文可达。

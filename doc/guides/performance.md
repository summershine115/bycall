# 对话链路性能复核与验证

> 更新：2026-10-18。属于执行计划 T1.4 / T1.9 / T2.5 的既有链路修复；不扩展冻结能力。

## 已确认并修复

| 问题 | 实现与边界 |
|---|---|
| 发布检查按文档逐条查询 manifest，并读取不需要的正文 | `rag/publication.py` 在 SQL 内筛选完成状态、知识域与职级，单条 LEFT JOIN 读取文档 ID 和有效代；无登记的历史文档仍使用旧代。ACL 与发布门保持召回前执行 |
| 流式前置同步调用阻塞事件循环 | 前置处理进入标准库线程池，8 个工作线程、运行加排队共 16 个槽位；满载返回 `busy`。线程独占 Session，只返回消息、能力值与工具；ContextVar 在执行工具的 Task 内安装和恢复 |
| 流式工具直接 `invoke` 阻塞事件循环 | 使用 LangChain 标准 `ainvoke`；同步工具通过其执行器运行，保留能力与审批 ContextVar；保持逐个执行，不改变工具顺序 |
| 工具调用后等待额外的记忆提取 LLM 才结束回答 | 主回答历史和审计提交后，后台提取；提取模型调用前关闭设置读取事务，写入再开事务；每批仅读取一次去重内容，保留 admin 权威与 superseded 不复活语义 |
| 后台压缩队列无界、会话锁表持续增长 | 压缩与记忆提取共用标准库线程池（2 个线程，运行加排队共 34 个槽位），满载跳过可选维护；压缩按会话合并，任务结束删除登记；历史压缩仍由 DB 租约保护 |
| 压缩缺少实际租约、模型失败仍推进摘要指针 | 压缩使用独立 Session 获取并提交现有 DB 租约，模型等待前归还连接；成功后条件更新摘要与指针，仅当前 token、未过期租约和未变化的旧摘要可发布；失败不推进，IM 在 turn 租约释放后再调度 |
| zvec 每次关闭都刷盘、全堆 GC | 跟踪写入状态，只有未 flush 的修改才在关闭时刷盘；释放最后一个 collection 引用关闭句柄，不调用全堆 GC；以跨进程重开测试验证写锁释放 |
| 记忆召回 `.all()` 构造全部 ORM 实体 | admin 相关性扫描使用分批标量读取，排序只保留分数、ID、长度，最后读取实际选中实体；agent 记忆分批读取、预算满足即停止；零预算返回空 |
| 无权 KB 也参与枚举和查询改写判定 | KB 可见性下推 SQL，改写存在性查询限制一行；不读取全部 KB 再做 Python 过滤 |
| 关键词降级排序重复统计同一词项文档频率 | 使用标准库 Counter 预计算一次，保留原有 BM25 分数和排序语义 |

后台维护是**有界、尽力执行的进程内任务**，不提供持久化队列或进程崩溃恢复。满载或停机可跳过记忆提取，压缩在后续轮次重试；原始历史与审计先提交，不依赖维护成功。线程中的阻塞调用不能通过取消 asyncio 等待强行终止；前置任务取消后仍占用槽位直到真正结束，Session 由工作线程关闭。外部模型仍受模型客户端现有超时及重试约束。

## 复核后收窄的判断

- 多 KB 串行不是独立的正确性缺陷。当前保留串行检索和逐次开关 collection，避免为未经压测证明的收益引入共享句柄、失效、入库写锁等复杂状态。候选总预算约束的是统一重排输入，不是此前全部检索工作；不能宣称全链路已有时间预算。
- 保留 admin 记忆的完整相关性排序和贪心字符预算，不简单截取前 N 条候选。全文评分仍需扫描有效记忆，排序元数据仍随条数增长；本次降低 ORM 和全文常驻内存开销，不宣称变为常数时间召回。
- 释放入口读取事务和记忆设置事务减少连接占用，不代表所有外部调用都已与 SQL 事务彻底分离；前置 RAG 管线中的连接占用仍需真实部署观测。
- zvec 句柄释放在 Python 3.12 / 当前 zvec 0.5.1 上验证；更换运行时或 zvec 版本应继续运行真实后端回归。
- 前端已有懒加载和按需组件分包，本次未发现需要优先修改的打包问题。

## 验证方式

```bash
make ci-local
python -m pytest tests/unit/test_performance_regressions.py tests/unit/test_graph_stream.py -q
```

2026-10-18 验证结果：`make ci-local` 通过，985 项测试、35 条四类综合评测、21 条权限安全评测全部通过；ruff 格式与 diff 检查通过。

新增回归不依赖绝对毫秒阈值，检查以下行为：

- 10 / 1,000 篇文档均只执行一次发布检查 SQL，覆盖权限、职级、状态、旧代与未发布代。
- 用线程事件暂停检索/工具，事件循环仍能调度；能力和审批上下文不会串到另一个 Task。
- 单连接池验证主模型等待和记忆提取期间相关读取事务已归还连接。
- 同步与流式回答均不等待可选记忆提取；审计先于提取完成可见。
- 排队上限、压缩合并、取消时工作槽位释放、跨进程重开 zvec。
- 压缩等待期间无连接占用，空结果和模型失败不推进指针，租约过期/抢占及新摘要写入阻止旧任务覆盖。

本机内存 SQLite 的 1,000 篇文档发布检查复测：单次查询，7 次中位数约 1.37ms。
先前检查为 1,001 次查询、单次约 86.8ms；采样方法不同，不据此声称固定加速倍数。
SQL 次数的回归断言比绝对耗时更稳定。

这些是局部可重复验证，不是生产吞吐量承诺。真实部署建议以 1 / 5 / 20 个 KB、
10 / 100 / 1,000 篇文档、1 / 10 / 30 个并发会话，分别测试普通回答、工具调用和入库期间检索。
先用固定延迟模型隔离平台开销，再接真实模型测首字、最终结束帧和 P95 延迟、连接池等待、
事件循环延迟和内存；同时保持未授权召回为零及会话隔离回归。
